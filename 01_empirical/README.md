# Empirical reproduction

This package reproduces the forecasting and statistical analyses in *Climate Policy Uncertainty and Predictive Information in Open Investor–Firm Communication Systems*. It uses the manuscript's 61-firm daily panel, ten rolling windows, fixed model settings, and seed 42. The original experiment numbers are recorded in [manifest.yaml](manifest.yaml).

## Install

Use a separate Python 3.12 environment for this package. From the repository root:

```sh
python -m venv .venv-empirical
# macOS/Linux
source .venv-empirical/bin/activate
# Windows PowerShell: .venv-empirical\Scripts\Activate.ps1
python -m pip install -r 01_empirical/requirements.txt
```

The root requirements belong to the existing text-processing workflow. The pinned empirical requirements record the environment used for this release's numerical checks.

## Configure inputs

Copy `01_empirical/config/paper.yaml` to `01_empirical/config/paper.local.yaml` and edit the input paths. Paths are resolved relative to the YAML file. Defaults refer to the repository's ignored `private/` directory. The [data dictionary](docs/data_dictionary.md) defines the schemas and historical input versions.

The baseline, original interaction archive, NEV index, CCPU, EPU, and exposure workbooks are supplied locally. Exact reproduction uses the historical processed feature panel and separately precomputed daily sentiment series described in Section 3.2. The existing text workflow produces newly extracted event features; these are not interchangeable with the historical daily panel without the aggregation and sentiment inputs below.

## Execute

Run from the repository root, in order:

```sh
python 01_empirical/run.py --config 01_empirical/config/paper.local.yaml --phase descriptive
python 01_empirical/run.py --config 01_empirical/config/paper.local.yaml --phase selection
python 01_empirical/run.py --config 01_empirical/config/paper.local.yaml --phase models
python 01_empirical/run.py --config 01_empirical/config/paper.local.yaml --phase ranking
python 01_empirical/run.py --config 01_empirical/config/paper.local.yaml --phase tables
python 01_empirical/run.py --config 01_empirical/config/paper.local.yaml --phase climate
python 01_empirical/run.py --config 01_empirical/config/paper.local.yaml --phase source
python 01_empirical/run.py --config 01_empirical/config/paper.local.yaml --phase residual
python 01_empirical/run.py --config 01_empirical/config/paper.local.yaml --phase exposure
```

`--phase all` executes that sequence. `models` fits 120 dynamic-feature combinations and 100 fixed-four-feature combinations. The later analysis stages reuse the saved predictions. `residual` and `exposure` are the checks discussed in Section 4.4; they do not retrain forecasts. Each run records configuration, software versions, and available input/prediction hashes. Reusing an output directory overwrites that stage's generated files.

## Evaluate frozen predictions

To reproduce statistical tables without retraining, place the original forecasts and metrics in this structure beneath the configured output directory:

```text
forecasting/dynamic/predictions/window_001_XGBoost_tech.parquet ...
forecasting/dynamic/window_metrics.csv
forecasting/dynamic/feature_selection/window_001_feature_selection.csv ...
forecasting/dynamic/feature_selection/selected_features.json
forecasting/fixed/window_metrics.csv
descriptive/market_regimes.csv
```

There are 120 dynamic prediction files, including 40 XGBoost files for four feature groups. The `source`, `climate`, `residual`, and `exposure` phases require the 40 XGBoost files. `source` additionally needs only the regime table; the other three use the baseline and relevant external inputs. `ranking` uses all 120 dynamic forecasts and the baseline. `tables` requires ranking results, selection tables, and fixed-track metrics.

## Optional historical panel preparation

These commands implement the original technical indicators, text aggregation, and common-stock sentiment replacement. Inputs are described in the data dictionary.

```sh
python 01_empirical/prepare_market.py --market private/market.csv --output outputs/01_preparation/market_features.csv
python 01_empirical/prepare_daily.py --interactions private/record_features.csv --market-features outputs/01_preparation/market_features.csv --output outputs/01_preparation/features.csv
python 01_empirical/prepare_baseline.py --features outputs/01_preparation/features.csv --sentiment private/sentiment.parquet --output private/baseline.parquet
```

The event pipeline shifts timestamps at or after 15:00 by one calendar day, then aligns non-trading-day observations with the next observed trading day by arithmetic means. Count fields therefore become activity measures. Reply delays use calendar days, the historical 44-day cutoff, and the value 66 for recoded replies. The sample retains observations within 90 days of the first observed market date, matching the submitted manuscript. Continuous sentiment is replaced from the separately supplied daily series, with zero sentiment on zero-activity days.

## Statistical definitions

Tables 4–6 and A7 calculate daily cross-sectional MCC, average within each test window, then give windows equal weight. Undefined daily MCC denominators produce zero. IC and RankIC average valid daily correlations. Table 7 pools firm-days within each market–CCPU group. The CCPU test resamples 20-date circular blocks over the complete ordered test-date series. Table A7 resamples the same-sized blocks separately within each fixed window. Both use 5,000 repetitions and seed 42, keeping models, thresholds, and states fixed. Table 7 reports Holm adjustments over the nine MCC contrasts and all 36 contrasts across four metrics. Table A7 uses its own nine-comparison family.

Market regimes use the retrospective NEV-index slope per elapsed calendar day with cutoffs −2 and +2. CCPU is lagged one calendar day and classified with training-date quartiles. Residual CCPU uses EPU lagged two months, 20-trading-day NEV volatility and return, and a trend; transformations and regression coefficients are fitted in training. Exposure becomes available the day after its recorded annual-report publication date, using the latest available fiscal year and training firm-year medians.
